# Демо-клуб: /promo4gym «Посмотреть демо-клуб» → demo.gym.trfnv.ru

Статус: **проект (архитектура зафиксирована, реализация по фазам ниже)**.

## Зачем

На промо-лендинге `/promo4gym` (сайт ИмпульС, gym.trfnv.ru) кнопка
«Посмотреть демо-клуб» сейчас просто якорит на `#lead-form`. Владелец зала
должен **пощупать продукт руками**: открыть «живой» демо-клуб, где есть
филиал, тренер со своими спортсменами и атлеты с разными историями
(регулярный с прогрессом / нерегулярный / ушедший), посмотреть аналитику
удержания и даже **попробовать всё**: записать тренировку, создать программу,
подтвердить заявку.

## Решения заказчика (зафиксированы)

1. **Контент демо** — полный демо-клуб: филиал, тренер, несколько атлетов
   с разными историями, аналитика владельца, портал тренера, приложение
   атлета; посетитель переключается между ролями.
2. **Точка входа** — кнопка «Посмотреть демо-клуб» на `/promo4gym`.
3. **Антибот** — IP-лимит + одноразовый токен (без капчи): не больше N токенов
   в час с одного IP; токен одноразовый, короткоживущий, привязан к IP.
4. **Изоляция** — **свой клон демо-клуба на каждую сессию** (посетитель может
   писать что угодно; чужие демо-клубы и тем более реальные данные не видны).
5. **Действия** — в демо можно пробовать всё (read-write).
6. **Жизненный цикл** — данные создаются «на лету» при входе, живут одну
   сессию (TTL), при выходе/истечении **полностью удаляются**.
7. **Хостинг демо** — отдельный домен `demo.gym.trfnv.ru`, отдельный контейнер
   и **своя БД** (паттерн `docker-compose.prod.yml` для impulse.trfnv.ru:
   db+redis+api+web самодостаточным стеком). Реальный прод gym.trfnv.ru и его
   БД демо не касаются вообще.

## Почему отдельный домен (ключевое архитектурное решение)

Текущий прод (gym.trfnv.ru) — **один сетевой инстанс без мульти-тенантности**:
роль `owner` видит всех пользователей и филиалы, `POST /api/admin/impersonate`
доступен только owner, аналитика скоупится ролью (owner=всё, manager=свой
филиал, trainer=свои атлеты). Встраивать «клон на сессию» внутрь прод-БД =
прорезать изоляцию во всех списках и аналитике рядом с реальными данными —
дорого и рискованно. Поэтому демо живёт в **отдельном развёртывании той же
кодовой базы** (`DEMO_MODE=1`), где в БД физически нет ничего, кроме
демо-клонов.

## Как устроен клон (целевая схема)

Каждая демо-сессия = уникальный `demo_session` id (например `ds_<rand>`).
При входе создаётся полный изолированный набор:

- `branches`: филиал «ИмпульС · Демо-клуб», `id = demo-<ds>`.
- `admin_users`: демо-владелец (role `owner`, `demo_session=ds`) и демо-тренер
  «Андрей Смирнов (демо)» (role `trainer`, `demo_session=ds`, `branch_key` =
  демо-филиал).
- `db.users` + файлы состояния `state-<uid>.json`: **3 атлета**:
  - **Артём** — регулярный ~6 мес: история тренировок с прогрессом, цели
    (одна достигнута), баллы/награды, привязан к демо-тренеру;
  - **Вероника** — ~2 мес, нерегулярно, средний прогресс;
  - **Дмитрий** — ходил 3 недели, потом пропал (кейс ухода для вкладки
    «Удержание»).
  Формат состояния = тот же JSON-блоб, что пишет `PUT /api/data`
  (`readState`/`stateFile` в api/server.js).
- История генерируется **серверной фабрикой** (чистая функция, по образцу
  frontend `src/lib/demoSeed.js`): режимы, веса, подходы, effort/оценки,
  body-weight тренд. После генерации — `replaceAthleteMetrics(uid, S)` /
  `backfillAthleteMetrics` для мгновенной аналитики.
- `loyalty_rules` демо-филиала (посещение/тренировка/серия), кошельки и
  ledger-записи атлетов (`loyalty_accounts`, `loyalty_ledger`), пара
  уведомлений.
- `trainer_availability` + `coach_bookings` демо-тренера (пара будущих
  записей), `trainer_assignments` (тренер ↔ 3 атлета).

### Сессии и переключение ролей (переиспользуем существующее)

- Вход без passkey: `POST /api/demo/enter` (авторизация = одноразовый токен)
  **сам выпускает** cookie сессии демо-владельца
  (`adminsid`, `admin:<ownerId>`, как `adminSessionCookie`), redirect на `/admin`.
- Переключение ролей — через существующий `POST /api/admin/impersonate`:
  владелец → атлет (`gymsid`, redirect `/`), владелец → тренер
  (`impersonate:` adminsid, redirect `/trainer`). UI владельца в аналитике уже
  умеет «войти как» (кнопки на карточках атлета/сотрудника).
- **Демо-скоуп (DEMO_MODE=1)**: demo-владелец видит в списках/аналитике
  только объекты своего `demo_session`. Реализация — точечный фильтр там, где
  это нужно (listAdmins, список users в аналитике, collectAnalytics,
  athleteDetail, retention, listBranches, loyalty-списки демо-филиала), плюс
  ограничение impersonate рамками своего demo_session. Фильтры включаются
  ТОЛЬКО при `DEMO_MODE=1` — прод-поведение не меняется.

### Антибот и жизненный цикл

- `POST /api/demo/token` (публичный): лимит `DEMO_TOKENS_PER_IP_PER_HOUR`
  (по умолчанию 5) на IP (считать по `X-Forwarded-For` первого хопа за
  nginx). Возвращает одноразовый токен, `expires_at` = +15 мин.
- `POST /api/demo/enter { token }`: токен одноразовый, не истёк, IP совпал →
  спавн клона (если ещё нет) → выпуск сессии демо-владельца. При повторном
  enter с той же сессии — вернуть существующую (идемпотентно).
- `POST /api/demo/end`: явный выход — полное удаление клона.
- Фоновый cleanup (по образцу `retention-runner.js`, каждые ~10 мин + при
  старте): удаляет клоны с `expires_at` < now (TTL `DEMO_SESSION_MIN`,
  по умолчанию 60) и все демо-сущности сессии. Демо-данные в демо-БД не
  накапливаются.

## Промо-страница

`frontend/public/promo4gym.html` — статика. Кнопки «Посмотреть демо-клуб»
(#hero и нижний CTA) получают `href="https://demo.gym.trfnv.ru"` (можно с
`?ref=promo4gym` для счётчика). Страница демо-развёртывания `/demo`-лаунчер
не нужен — сразу вход владельца (посетитель дальше сам выбирает роль
кликами «войти как»). (Опционально позже: отдельная страница-заставка с
выбором роли.)

## Развёртывание demo.gym.trfnv.ru

- Директория на ВПС: `/opt/opengym-demo` — клон репозитория (ветка dev).
- `.env`: `ORIGIN=https://demo.gym.trfnv.ru`, `RP_ID=demo.gym.trfnv.ru`,
  `DEMO_MODE=1`, `DATA_DIR=/data`, свои `SECRET`/`DATABASE_URL` (БД стека),
  `WEB_PORT=8181`.
- `docker-compose.prod.yml` используется как compose (db+redis+api+web),
  `docker compose -p opengym-demo up -d --build`.
- nginx на ВПС: `demo.gym.trfnv.ru.conf` → `127.0.0.1:8181`
  (копия gym.trfnv.ru.conf), certbot-сертификат.
- DNS: `demo.gym.trfnv.ru` → IP ВПС (прописывает владелец).
- В демо-режиме отключается внешняя почта/пуши (или пуши в «демо»-режиме не
  отправляются реально), чтобы не слать уведомления от чужого имени.

## Ralf-план (каждая фаза: build → автотесты → CHANGELOG → версия → commit → push в dev)

- **Ф0. Инфраструктура (репо, без деплоя)**: env `DEMO_MODE` в api
  (server.js читает флаг), таблицы `demo_tokens`/`demo_sessions` в
  admin-db.js (миграция), функции token/session CRUD. Тесты БД.
- **Ф1. Токены + антибот**: `POST /api/demo/token` с IP-лимитом. Тесты
  лимита (unit через чистую функцию + интеграция лимита по IP).
- **Ф2. Клон-генератор** `api/demo-club.js`: чистая фабрика состояния
  атлетов (3 истории) + серверный спавн всего набора + backfill метрик.
- **Ф3. Enter/End/cleanup**: `POST /api/demo/enter`, `POST /api/demo/end`,
  фоновый cleaner (TTL 60 мин). Полное удаление клона — тест «спавн →
  данные есть → end/cleanup → данных нет».
- **Ф4. Демо-скоуп в списках/аналитике** (DEMO_MODE=1): фильтр
  listAdmins/users/collectAnalytics/athleteDetail/retention по
  `demo_session`, impersonate только внутри своего клона. Тесты изоляции
  «два клона не видят друг друга».
- **Ф5. Промо-кнопка** → `https://demo.gym.trfnv.ru`.
- **Ф6. Деплой** demo.gym.trfnv.ru (стек + nginx + DNS + certbot), сквозная
  проверка: токен → клон → владелец → «войти как» тренер/атлет → правки →
  выход → клон удалён. Backfill retention в демо-БД по ночам — не нужен
  (данные пересоздаются на спавне).

## Риски и ограничения

- Фабрика историй должна повторять форму реальных state-файлов (проверять
  `modeOf`/`history` схему из frontend `src/lib/history.js` и
  `demoSeed.js`), иначе вкладки статистики/удержания покажут пустоту.
- Имперсонация в демо ограничена своим клоном — ни в коем случае не
  ослаблять это в проде (фильтр строго под `DEMO_MODE=1`).
- Пуши/email в демо не отправлять наружу (флаг заглушки).
