# Ветка `demo` — демо-развёртывание и политика стабильных релизов

> Короткая шпаргалка для агентов и разработчиков. Полный контекст демо-клуба
> (архитектура, клон на сессию, антибот, изоляция) — в `docs/demo-club.md`.

## Зачем ветка `demo`

`demo.gym.trfnv.ru` — **витрина для потенциальных клиентов** (владельцы залов,
менеджеры). Она должна показывать продукт в лучшем виде, поэтому ей нельзя
отдавать недоделанные фичи из `dev`. Политика:

- **`dev`** — повседневная разработка (все коммиты v1.x, тесты, CHANGELOG).
  Прод `gym.trfnv.ru` крутится прямо с `dev` (рабочий инстанс владельца).
- **`demo`** — стабильные релизы. Обновляется ТОЛЬКО осознанным merge
  `dev → demo` после того, как релиз проверен (api-тесты + frontend + build +
  ручная проверка на проде).

Демо **осознанно отстаёт** от dev на ту работу, что ещё не признана стабильной —
это фича, а не баг. От стабильных релизов демо не отстаёт никогда.

## Схема веток

```
dev  ──●────●────●────●────  (разработка, прод gym.trfnv.ru)
        \         \
demo ────●─────────●───────  (только стабильные срезы → demo.gym.trfnv.ru)
```

## Как выпустить релиз в демо

```bash
# 1) На прод-сервере (82.202.141.81), в /opt/opengym (рабочая копия dev):
cd /opt/opengym
git checkout dev && git pull origin dev
#     …прогнать api-тесты + frontend + build (см. docs ниже)…

# 2) Влить проверенный dev в demo и запушить ОБЕ ветки:
git checkout demo
git merge dev            # demo получает очередной стабильный срез
git push origin demo
git checkout dev

# 3) Развернуть на демо-стек:
cd /opt/opengym-demo
./deploy-demo.sh         # git pull demo → build api+web → up -d
```

Перед merge стоит убедиться, что `CHANGELOG.md` пополнен и версия в шапке
соответствует последнему релизу — так по логам demo-стека видно, что именно
показывает витрина.

## Где что лежит на сервере (82.202.141.81)

| Путь | Роль | Ветка |
|---|---|---|
| `/opt/opengym` | рабочая копия репо, **прод** gym.trfnv.ru (nginx → 127.0.0.1:8180) | `dev` |
| `/opt/opengym-demo` | **демо** demo.gym.trfnv.ru (nginx → 127.0.0.1:8181), свой стек `docker-compose.demo.yml` (db+redis+api+web), своя БД | `demo` (git-чекаут) |
| `/opt/opengym-demo/.env` | DEMO_MODE=1, ORIGIN/RP_ID=demo.gym.trfnv.ru, свой WEB_PORT=8181, пароль своей БД | вне git |
| `/opt/opengym-demo/data` | runtime api: db.json, secret, vapid.json, state-*.json | вне git |
| `/opt/opengym-demo/media` | симлинк на `/opt/opengym/media` (картинки/гифки упражнений) | вне git |

`docker-compose.demo.yml` и `deploy-demo.sh` лежат В git (ветки dev/demo) —
это единственный источник правды по демо-стекам, не редактируйте копии вручную.

## Важные правила демо-развёртывания

1. **DEMO_MODE=1** включает демо-контур: `/api/demo/*` эндпоинты, cleaner,
   скоуп `demo_session` в аналитике/списках, лаунчер «Открыть демо-клуб» на
   логине, скрытая вкладка «Приватный». На проде `DEMO_MODE` не задан — всё это
   выключено.
2. **Изоляция клонов**: каждый посетитель демо получает свой клон
   (филиал + владелец + тренер Андрей + 3 атлета), чужие клоны не видны.
   Клон живёт TTL 60 мин и полностью удаляется cleaner'ом или при `/api/demo/end`.
3. **Бэкапы перед крупными изменениями** (правило проекта):
   `sudo tar czf /opt/backups/opengym-demo-pre-<что>-<дата>.tar.gz -C /opt opengym-demo`
   + `pg_dump` демо-БД + git-тег точки отката.
4. **Не коммитить**: `.env`, `data/`, `media/`, `backups/` (в .gitignore).
   Секреты демо (.env, data/secret, vapid.json) живут только на сервере.
5. Если стек демо «поплыл» (не собирается/не стартует) — откат:
   `cd /opt/opengym-demo && git reset --hard <предыдущий-stable-коммит> && ./deploy-demo.sh`.

## Проверка после деплоя

```bash
curl -s https://demo.gym.trfnv.ru/api/config          # → {"invite_only":false,"demo":true}
curl -s -X POST https://demo.gym.trfnv.ru/api/demo/token   # → {"token":"…","ttl_min":15}
# открыть https://demo.gym.trfnv.ru → «Открыть демо-клуб» → панель владельца →
# переключиться на тренера Андрея и атлетов → закрыть → cleaner уберёт клон.
```

Полный цикл демо-сессии и e2e-скрипты описаны в `docs/demo-club.md`.
